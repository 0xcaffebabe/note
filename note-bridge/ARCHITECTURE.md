# note-bridge 代码组织与维护约定

本项目沿用核心站点的职责划分思路：数据契约描述边界，端口隔离外部能力，服务实现业务，平台入口只做组装。按变化原因拆分模块，不以行数作为唯一标准，也不为每个函数增加一层无意义的接口。

## 职责与数据归属

| 层次 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| 桌面 UI | 配对、模型配置、日志的展示和用户操作 | 直接操作凭据库、执行 Agent 循环 |
| Tauri 入口 | 命令适配、托盘、窗口和进程生命周期 | 模型协议、网站工具或会话业务 |
| Rust bridge-core | 本机授权、配置与凭据、WebSocket 网关、worker 管理 | 聊天 transcript、模型上下文拼接 |
| Node Agent | Pi 组装、运行策略、持久任务、知识工具和会话投影 | 将网站内容变成本地权威副本 |
| 知识站点 | 独立发布正文、TOC、图谱、聚类和检索资源 | 保存或执行 Agent 任务 |

数据格式与网络协议见 [PROTOCOL.md](PROTOCOL.md)、[KNOWLEDGE_PROTOCOL.md](KNOWLEDGE_PROTOCOL.md)。本文件说明代码边界，不重复维护另一份协议或运行限制。

## Rust 原生服务

`crates/bridge-core/src/lib.rs` 只声明模块与公开导出。公开类型和方法路径保持稳定，内部实现按职责维护：

| 模块 | 主要边界 |
| --- | --- |
| `bridge/` | 门面组装、状态契约、监听生命周期、配对/撤销、模型管理、日志和 worker 配置同步 |
| `bridge/gateway/` | Origin/Host 准入、首次认证、连接生命周期、产品 RPC 分派和有界输出 |
| `agent/` | 子进程启动/回收、JSONL 拆帧、请求关联和超时；不解释产品会话业务 |
| `discovery/` | 有界文件读取、候选指纹、Claude 解析和 Codex 认证/profile/catalog |
| `storage/` | 凭据端口与内存/系统适配器、JSON 配置校验与原子落盘 |
| `model/` | 服务契约、模型能力与预算、字段和端点校验 |
| `model_catalog/` | 模型目录的纯解析与远端 HTTP 分页 |
| `authorization.rs`、`origin.rs` | 网站令牌摘要持久化与共享的精确来源校验 |

同一个 `Bridge` 的实现按职责放入多个模块，不另建各自拥有授权副本的服务。`bridge/state.rs` 的可见性限于门面内部：配对码消费、授权文件提交、连接登记和撤销必须共享同一把状态锁；启动/停止另由生命周期锁串行。拆文件不能拆散这些原子边界。

worker 槽锁保证旧进程关闭后才启动替代进程。认证响应在 worker 配置同步后发送，事件订阅在存活检查前创建；撤销同步失败即关闭 worker。连接清理依次结束通道、等待已准入 RPC、detach 订阅，再移除连接登记。

存储门面保留跨 JSON 和系统凭据库的事务协调：先保存新的凭据条目，再原子提交端点与凭据引用，最后清理旧条目。JSON 写入失败清理暂存凭据；删除凭据失败尝试恢复原 JSON。`provider_with_secret` 在同一锁内读取端点和凭据，禁止调用方用两次独立读取自行拼接。

配置发现只静态读取用户选定来源，不执行 CLI/helper。候选指纹涵盖源内容、凭据和模型目录，导入前重新核验。候选不能实现会打印凭据的 `Debug`，非法原始 URL 也不能通过序列化暴露给界面。

## Node Agent

`agent/src/index.ts` 是进程启动入口，`runtime.ts` 是服务组装和产品 RPC 门面。它们不实现各业务步骤；新增业务应归入对应服务。

| 目录 | 变化原因 |
| --- | --- |
| `domain/` | 领域数据契约、状态和业务错误 |
| `config/` | 运行预算、系统提示词和 Pi 配置策略 |
| `protocol/` | 已认证请求上下文、请求校验和运行时参数 |
| `ipc/` | 有界 JSONL 输入输出、宿主命令分发和请求优先级 |
| `persistence/` | Pi document 定义、会话身份映射和检查点查询 |
| `services/` | 会话管理、回合准入、生命周期、授权策略、准备阶段取消和订阅 |
| `projection/` | 从已提交 transcript 生成可展示的回答、工具记录与引用 |
| `model/` | 模型选择、协议参数转换、有界 HTTP 传输和 Pi stream 适配 |
| `knowledge/` | 独立知识协议、资源校验、HTTP 读取与只读知识工具 |
| `adapters/` | 将知识工具和运行策略注册到 Pi |

`types.ts`、`models.ts` 和 `knowledge.ts` 仅保留对外导出。模块内部优先依赖具体的领域契约或服务，避免通过聚合导出产生不透明的循环依赖。

持久化服务不强行包装每一种 Pi 操作。需要同时更新会话索引和运行记录的业务步骤，仍由业务服务在同一个 Pi 事务内提交。重构不能把这一事务拆成多个彼此独立的“保存”调用。

关键约束：

- 每个数据库只由一个 worker 持有。启动先恢复所有 provider 会话身份映射，再恢复任务并启动 Pi 调度。
- 同会话写操作串行。取消先中断知识准备阶段，再进入会话队列，避免等待网络读取才能停止。
- 授权、模型配置和预算在执行边界重新检查；长时间网络读取后必须再次验证。
- 取消状态先落盘，再中断执行；宿主关闭只释放资源，未完成任务由下次启动恢复。
- 网页只消费已提交投影。断开、切换会话和取消订阅不等于取消任务。
- API 凭据只在 HTTP 实际发送时注入，不写入 Pi stream options、检查点、错误正文或日志。

知识模块通过独立协议访问网站，不引用核心站点源码。HTTP 层负责大小、超时、重定向和 hash 校验；资源解析层负责结构验证；文档、发现和检索服务负责各自工具语义；快照只做同一内容版本的组装。实时检索片段只用于定位文档，引用依据已验证的正文。

## 桌面界面

`src/App.svelte` 负责组装和导航。`core/domain/` 保存界面使用的数据与纯表单规则，`core/ports/DesktopBridgePort.ts` 定义原生能力端口，`adapters/TauriDesktopBridge.ts` 集中维护命令名和参数序列化。

`application/` 保存有生命周期的界面状态：桌面快照与操作协调、提供方列表操作、模型编辑状态。`views/` 和 `components/` 负责渲染和用户事件；焦点约束与恢复位于 `actions/`。组件不得自行散落调用 Tauri `invoke`，也不自行复制后端配置校验。

`src-tauri/src/lib.rs` 只组装应用，`commands.rs` 转换桌面命令，`tray.rs` 处理托盘与窗口生命周期。命令失败应保留领域错误语义，不把凭据或上游响应作为诊断文本返回。

## 编写和审查约定

- 契约、数据模型和执行逻辑分开；紧密相关的小型类型可放在同一领域文件，不机械要求“一文件一类型”。
- 函数保持同一抽象层级。用命名步骤表达“校验、读取、提交、通知”，避免长函数同时处理协议解析和业务事务。
- 展开 `if`、循环和异常分支；避免分号串接语句、逗号串接声明、嵌套三元表达式和巨大单行对象。
- 重要类、接口、端口及生命周期方法使用 TSDoc 或 Rust `///`。解释所有权、失败语义、事务边界、资源释放和设计原因，不重复方法名。
- 对外 API 尽量保持稳定；内部依赖采用精确导入和最小可见性，不通过公开整个可变状态图来简化接线。
- 新增抽象应有实际的隔离或复用价值。禁止用通用 `utils`、服务定位器或层层透传掩盖职责不清。
- TypeScript/Svelte 使用本目录 `.prettierrc.json`，Rust 使用 rustfmt。`npm run format` 格式化源码；`npm run format:check` 和 CI 检查格式。

## 验证重构

优先运行现有行为测试，验证公开契约，不围绕新的私有文件结构编写重复测试。知识资源校验、授权撤销、幂等提交、工具预算、取消持久化和进程崩溃恢复是关键回归点。

常用命令见 [README.md](README.md#开发与构建)。Agent 编译完成后再运行 Rust→Node→Pi 集成测试，避免误测旧的 `agent/dist`。桌面组件拆分后执行 Svelte 检查、生产构建和现有 UI E2E；原生命令拆分还需检查 Tauri crate。没有变更的网站页面无需重复设计 UI。
